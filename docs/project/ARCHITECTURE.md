# Архитектура и поведение агента

## Назначение и входы

`run_agent.py` принимает `--tasks-dir`, `--out`, `--strategy`. Каталог задач
содержит подкаталоги с `task.json` и, при необходимости, `workspace/`.
`tasks.scan()` отбрасывает поле `expected`, проверяет ID, награду и symlink на
верхнем уровне. Эталон ответа в каталог агента помещать нельзя.

```text
run_agent.py
  → Harness.scan → Task/AnswerStore
  → deterministic: math/search/data/coding
  → StrategyExecutor: order → budget_for → model_for → attempt
       → llm_solvers → LLM.chat → BudgetLedger → openJiuwen Model
       → sandbox/coding tests → accept_answer/accept_code
  → optional endgame verification → results.json / answer.txt / trace
```

`Harness` управляет жизненным циклом, дедлайном и бесплатной фазой. Исполнитель
перед каждой попыткой пересобирает `RunState`. Стратегия выбирает порядок,
модель и лимит, но не вызывает сеть и не записывает ответы. `LLM` является
единственным шлюзом физических запросов; первичный транспорт — openJiuwen
0.1.19, прямой HTTP допустим в текущей реализации только после сбоя
конструирования SDK до отправки запроса. После неопределённого исхода отправки
реестр блокирует новые вызовы.

## Фазы и статусы

1. Детерминированные решатели пытаются получить проверяемый результат без LLM.
   Math разбирает известную грамматику, Search проходит граф локальной KB,
   Data Analysis применяет строгие операции и фильтры, Coding использует
   тесты и ограниченный поиск исправлений. Неизвестная форма остаётся для LLM.
2. Исполнитель запускает до `HARNESS_WORKERS` задач (верхняя граница 5).
   Отдельная семафора LLM ограничивает физические вызовы до
   `LLM_CONCURRENCY` (по умолчанию 1). Общий ограничитель `LLM_RPM=30`
   выдерживает минимум 2 секунды между физическими вызовами всех моделей.
3. `empirical_hybrid` направляет Math/Coding в `qwen3.8-27b`, Search/Data
   в `qwen3.8-27b-noreason`. Порядок первой попытки: награда × априорная
   вероятность успеха / ожидаемый расход. Внутри coding возможен ремонт
   на основании фактической ошибки тестов.
4. После завершения первых попыток endgame сортирует текстовые ответы по
   ожидаемой ценности исправления. Он не запускается при `pending`, не
   перепроверяет Coding, оставляет 5000 конкурсных единиц плюс резерв
   `BudgetLedger`, соблюдает лимит 1500 на задачу и останавливается при
   остатке времени менее 240 с. Независимый ответ совпал — третьего вызова
   нет; при расхождении ответ меняется только при большинстве 2 из 3.
5. `AnswerStore` атомарно пишет `answer.txt` и сводный `results.json`.
   `HARNESS_TRACE` и `HARNESS_REQUEST_JOURNAL` задают отдельные траекторию
   и журнал физических запросов. Они должны указывать на доступные для
   записи пути и не содержать секретов.

`verified` означает прохождение локальных тестов Coding, а не официальный
балл. `answered_unverified` означает записанный текстовый ответ. `vote`
не превращает его в истину. `infeasible_claimed` — гипотеза. `failed` и
`skipped` различают неудачную попытку и незапущенную задачу. `DONE` сам по
себе не доказывает правильность Coding.

## Бюджет и ошибки

Стоимость: `output_tokens + input_tokens / 10`; reasoning-токены учитываются
по `HARNESS_REASONING_USAGE=included|separate`, который должен совпадать с
семантикой прокси. `BudgetLedger` выдаёт одноразовый ticket до отправки.
Подтверждённый usage закрывает ticket фактической суммой. Ошибка после
неопределённой отправки списывает полный резерв и останавливает реестр.
Область `cap_scope` ограничивает отдельную попытку, диагностику и vote;
общий реестр и лимит `HARNESS_TASK_CAP` остаются обязательными.
Отказы до отправки не считаются ошибкой решателя и не обучают ML.

`online_mlp` и калибровочные стратегии опциональны. Успех текстовых задач
нельзя обучать по статусу `answered_unverified`; для Coding допустим только
фактический исход публичных тестов. Исторический replay гибрида на 272
парных задачах и 2000 bootstrap-эпизодах дал 331,92 против 311,43 у Fast,
но не оценивал новый endgame и не является конкурсным результатом.

## Границы доверия

`sandbox.py` копирует workspace и запускает пользовательский Python с
лимитами ресурсов. Режим `HARNESS_ISOLATION=auto` использует Landlock/seccomp,
если доверенная проверка хоста показывает поддержку; иначе логирует
деградацию до ресурсных лимитов. Для полностью враждебного кода это не
доказанная граница: текущий private-validation report отмечает возможность
подмены вердикта в общем интерпретаторе. Закрытые эталоны должны находиться
в отдельном процессе оценивания и никогда не монтироваться в контейнер агента.

`tools/run_controlled.py` создаёт независимые эпизоды и сохраняет конфигурацию,
результаты и журнал. `tools/score320.py` и `tools/validation/` относятся к
оценщику; их нельзя использовать внутри конкурсного процесса. `tools/compare.py`
и `tools/stress_compare.py` проводят mock/real исследования. `tools/document_api.py`
строит точный каталог сигнатур исходника, включая внутренние методы.
